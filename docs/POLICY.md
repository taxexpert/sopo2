# 확정 정책 (사용자 결정 기록)

전임자 v54의 확정 규칙·금지 회귀는 [HANDOFF_V54.md](HANDOFF_V54.md)에 있다. 이 문서는
그 이후 사용자(세무법인 엑스퍼트)가 확정한 정책을 기록한다. 목적: 독립 검증이나
리팩터링 작업이 아래의 **의도된 동작을 오류로 재분류해 되돌리지 않게** 하는 것.

## 2026-07-30 확정

1. **출력 엑셀의 모든 기준일은 선적일자(기적일)를 사용한다.**
   영세율첨부서류의 발급일자 칸도 선적일자를 그대로 쓴다. 발급일자를 문서
   작성일(`write_date`)로 분리하는 변경은 제안됐으나 기각됐다. 환율 기준일·
   월별집계·향후 신고기간 분류의 기준일도 모두 선적일이다.
2. **영세율첨부서류 L/C 번호 칸의 운송장번호는 유지한다** (v54 확정 규칙,
   HANDOFF §7.2). 15열 양식의 대상 신고 시스템이 확인되면 재검토한다.
3. **기타영세율건수는 행당 1을 유지한다** (v54 확정 규칙, HANDOFF §8).
   집계 단위(주문/소포/증빙)는 대상 프로그램·세무대리인 확인 전까지 미확정.
   값 변경은 `modules/extra_docs.py`의 `other_zero_rate_count_value()` 한 곳에서 한다.
4. 신고기간 필터(`modules/reporting_period.py`, STEP 3)에서 기간 경계에 걸치는
   분할불가 집계자료(라자다 PDF·큐텐·이베이 월집계)는 자동 안분하지 않고
   **생성을 차단하고 재업로드를 요구**한다.
5. `partially_refunded` 전액 매출 처리와 원화 반올림 방식은 확인된 정책으로 유지한다.

## 중복 판단 기준 (2026-07-30 확정, `modules/dedup_guard.py`)

"같음"을 4단계로 구분하고, **자동 제외는 ①·②만** 한다.

| 단계 | 판정 | 처리 |
|---|---|---|
| ① 파일 바이트 동일 (SHA-256) | 확정 중복 | 파싱 전 제외 + 로그 |
| ② 강한 거래키 동일 + 내용 전부 동일 | 확정 중복 | 자동 제외 + 로그 |
| ③ 강한 거래키 동일 + 내용 다름 | 변경 충돌 | **자동 선택 금지, 생성 중단** |
| ④ 강한 키 없는 집계자료 | 판정 불가 | **자동 제외 금지**, 겹침 의심 경고만 |

플랫폼별 강한 거래키 (샘플 실측으로 유일성 확인 후 확정):

- 쇼피: (통화, 운송장번호) — 13개 PDF 통합 893건 전부 유일
- 라자다: (통화, orderItemId) — **주문번호·운송장은 키로 쓰지 않는다.** 같은 주문의
  상품행 분할(주문번호 29종 반복)과 합포장(운송장 25종 반복)이 정상 데이터다
  (v54 금지 회귀 8). orderItemId만 172건 전부 유일.
- 쇼피파이: (스토어, 주문명) — 상태만 바뀐 재수출(paid→refunded)은 내용 불일치로
  ③충돌이 되어 자동 삭제되지 않는다 (검증기준 T05)
- Joom: (order_id, 없으면 운송장)
- 이베이 월집계·큐텐 수동목록: 강한 키 없음 → ④ 경고만

사업자 혼합: 자료에서 읽힌 **사업자번호가 2개 이상이면 생성 중단**. 제출자 정보가
없는 자료(쇼피파이 orders)는 판정에 쓰지 않고, 미확인 제출자는 기존 정책대로
중립 문구로 계속 생성한다 (v54 §3.1).

## 미확정 (확인 트랙)

- 15열 양식(`forms/영세율첨부서류제출명세서 양식.xlsx`, 2011년 생성)의 대상 신고
  시스템 — 전임자에게 직접 문의(어느 프로그램에 어떻게 올렸는지)가 최단 경로.
- 기타영세율건수의 실제 공급 거래 단위 집계 규칙.
- Shopify orders 파일의 증빙 적격성(영세율 출력의 서류명 "소포수령증" 고정 문제).

## 양식 파일명 이력

v54 zip의 양식 파일명은 `영세율첨부서류명세서 양식.xlsx`("제출" 없음)였고, 이
저장소에는 `영세율첨부서류제출명세서 양식.xlsx`로 업로드됐다. 코드 조회는 저장소
파일명을 우선하고 구명칭을 읽기 호환 폴백으로 허용한다
(`modules/extra_docs.py`의 `ZERO_TEMPLATE_FILENAMES`).
