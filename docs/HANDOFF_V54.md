> 대상: 다른 ChatGPT/GPT가 이 프로젝트를 이어서 수정할 때 사용하는 컨텍스트 문서  
> 기준 버전: **`sopo_github_hybrid_v54.zip`**  
> 작성일: 2026-07-30  
> 우선순위: 이 문서의 “확정 규칙”을 일반적인 추측보다 우선 적용할 것

## 0. 작업 원칙

1. 현재 사용자가 실제로 계속 쓰기로 한 기준은 **v54**다.
2. 이후 수정은 반드시 v54를 기준으로 분기한다.
3. 과거 버전의 동작을 무심코 되돌리지 않는다.
4. 수정 후에는 가능하면 사용자가 올린 실제 샘플 파일로 회귀 테스트한다.
5. 결과물은 보통 다음 두 가지를 함께 제공한다.
   - 전체 프로젝트 ZIP
   - 기존 버전에 부분 적용할 때 교체할 파일 목록
6. Streamlit은 Python 모듈을 메모리에 유지할 수 있으므로, 코드 교체 후 브라우저 새로고침만으로는 반영되지 않을 수 있다. **프로세스/앱 재시작이 필요할 수 있다.**

# 3. 확정된 예외 규칙

## 3.1 제출자·사업자 정보 기본값

PDF나 라자다 Excel에서 사업자명을 읽지 못했을 때 특정 업체명인 `유엠`, `UM`을 절대 넣지 않는다.

### 기본 표시

```text
사업자명(사업자번호)
```

### 적용 위치

- 총집계 시트 상단
- 월별집계 시트 상단
- 영세율첨부서류 파일명
- 수출실적명세서 파일명
- 제출자 정보를 표시하는 플랫폼 시트

### 사업자번호·대표자·주소

확인되지 않으면 임의의 기존 업체 정보를 넣지 말고 공란 처리한다.

---

## 3.2 출력 문서 선택 기본값

Streamlit 최초 화면 체크 상태:

| 문서 | 기본 체크 |
|---|---|
| 매출집계 | 체크됨 |
| 영세율첨부서류제출명세서 | 체크됨 |
| 수출실적명세서 | **체크 안 됨** |

`수출실적명세서`를 다시 기본 체크 상태로 되돌리지 말 것.

---

## 3.3 미사용 플랫폼 시트·집계 제외

실제 입력 자료가 없는 플랫폼은 총집계에 표시하지 않는다.

예:

- 쇼피 자료가 없으면 쇼피 행 생략
- 라자다 자료가 없으면 라자다 행 생략
- 큐텐 자료가 없으면 큐텐 행 생략
- 이베이 자료가 없으면 이베이 행 생략

불필요한 빈 플랫폼 시트를 억지로 만들지 않는다.

# 4. 플랫폼별 규칙

## 4.1 쇼피

### 같은 통화 PDF가 여러 개일 때

원본 소포수령증 시트는 각각 분리한다.

```text
쇼피(MYR)(1)
쇼피(MYR)(2)
```

통화 집계 시트 `MYR`에는 두 PDF 거래를 모두 합쳐 날짜순으로 정렬한다.

### 환율

- 기본적으로 배송일/거래일 기준 일별 매매기준율
- 휴일·주말은 직전 영업일 환율
- JPY·IDR·VND는 아래 “100통화 단위 예외” 적용

---

## 4.2 라자다 PDF

기존 라자다 소포수령증 PDF 처리 기능은 유지한다.

라자다 PDF와 라자다 주문 Excel은 날짜·환율 기준이 서로 다를 수 있으므로 같은 로직으로 뭉개지 않는다.

- 라자다 PDF: 문서 기준일 또는 기존 정의된 기간 평균 방식 유지
- 라자다 주문 Excel: `deliveredDate`별 일별 환율 적용

---

## 4.3 라자다 주문내역 Excel

### 필수 필드

| 원본 열 | 사용 의미 |
|---|---|
| `paidPrice` | 외화 매출금액 |
| `deliveredDate` | 매출일·선적일·환율 적용일·월별집계 기준일 |

### 행 처리

- 주문번호가 같더라도 상품 행별 `paidPrice`를 각각 반영한다.
- 임의 중복 제거 금지.
- `deliveredDate`와 `paidPrice`가 유효한 행만 거래로 집계한다.

### 국가·통화 자동 판별

`shippingCountry` 또는 파일명을 이용한다.

| 국가 | 통화 |
|---|---|
| Vietnam | VND |
| Singapore | SGD |
| Thailand | THB |
| Malaysia | MYR |
| Philippines | PHP |
| Indonesia | IDR |
| Taiwan | TWD |

### 여러 국가 파일 동시 업로드

여러 국가 Excel을 한 번에 올리면 하나의 라자다 결과로 합산한다.

### `라자다(주문내역)` 시트

사용자가 원한 핵심 예외다.

- 새 집계표 형태로 재작성하지 않는다.
- 업로드한 국가별 원본 Excel 시트를 **원본 열·값·서식 그대로** 복사한다.
- 첫 파일 전체를 붙인 뒤 빈 행 1줄을 두고 다음 파일을 이어 붙인다.
- 원본의 전체 열을 유지한다. 샘플 기준 약 77열.
- 가능한 범위에서 아래를 보존한다.
  - 셀 값
  - 셀 서식
  - 숫자·날짜 표시 형식
  - 열 너비
  - 행 높이
  - 병합 셀
  - 숨김 행·열
  - 수식
  - 하이퍼링크

구조 예시:

```text
베트남 원본 헤더 + 데이터
빈 행 1줄
싱가포르 원본 헤더 + 데이터
빈 행 1줄
태국 원본 헤더 + 데이터
```

### `라자다(통화)` 상세 시트

예:

```text
라자다(VND)
라자다(SGD)
라자다(THB)
```

열 구성은 아래 9개만 사용한다.

```text
No
배송완료일
주문번호
주문상품번호
송장번호
배송사
외화금액
환율
원화금액
```

**`원본파일` 열을 다시 만들지 말 것.**

### 라자다 샘플 회귀 테스트 값

사용자가 제공한 샘플 3개 기준:

| 통화 | 거래행 수 | 외화 합계 |
|---|---:|---:|
| VND | 23 | 8,087,839 |
| SGD | 63 | 1,242.86 |
| THB | 89 | 48,281.89 |

해당 값은 파서 수정 시 회귀 테스트에 활용한다.

## 4.4 큐텐재팬

큐텐은 다른 플랫폼과 날짜·환율 기준이 다르므로 별도 처리한다.

### PDF 자동 인식

파일명에 `큐텐`, `Qoo10`이 없어도 PDF 본문에서 아래 표식을 확인해 자동 판별한다.

- `Qoo10`
- `국제로지스틱`
- `금액(JPY)`

### PDF에서 파싱할 정보

- 제출자 사업자등록번호
- 상호
- 대표자
- 주소
- 거래기간
- 작성일자
- 발송번호
- 수량
- 금액(JPY)

PDF 업로드 시 STEP 2 수동 입력 목록에 자동 반영한다. 수동 추가 입력 기능도 유지한다.

PDF 없이 큐텐 수동 입력만 있어도 문서 생성이 가능해야 한다.

### 날짜 기준: 작성일이 아니라 반기말

큐텐은 다음 모든 날짜를 거래기간의 반기말로 본다.

| 거래기간 | 신고 기준일 |
|---|---|
| 상반기 | 해당 연도 6월 30일 |
| 하반기 | 해당 연도 12월 31일 |

적용 위치:

- 월별집계 월
- `JPY` 통화 시트의 선(기)적일자
- 영세율첨부서류의 발급일자
- 영세율첨부서류의 선적일자
- 수출실적명세서의 선(기)적일자

거래기간 종료일이 있으면 그 날짜를 우선 사용한다. 없으면 거래기간 시작일 또는 작성일로 상·하반기를 추정한다.

예:

```text
거래기간: 2026-01-01 ~ 2026-06-30
PDF 작성일: 2026-07-10
신고·집계일: 2026-06-30
```

### 환율 기준: 큐텐만 월평균환율

큐텐재팬 거래는 일별환율이나 거래기간 평균이 아니라 서울외국환중개의 **반기말 월 공식 월평균 매매기준율**을 사용한다.

| 거래기간 | 적용 월평균환율 |
|---|---|
| 상반기 | 해당 연도 6월 월평균 JPY 환율 |
| 하반기 | 해당 연도 12월 월평균 JPY 환율 |

이 환율을 큐텐재팬에 한정하여 아래 전부에 동일하게 적용한다.

- 총집계
- 월별집계
- `JPY` 통화 시트
- 큐텐 소포수령증 시트
- 영세율첨부서류제출명세서
- 수출실적명세서

### `환율(JPY)` 시트

큐텐 자료가 있으면 필요한 반기말 월의 공식 월평균 환율도 표시한다.

- 상반기 자료: 6월
- 하반기 자료: 12월
- 상·하반기 자료가 함께 있으면 6월과 12월 모두

`환율(JPY)` 시트의 월평균 값은 서울외국환중개 원문과 동일한 **100엔 단위 값**으로 표시한다.

### 큐텐 테스트 기준

기존 샘플:

```text
거래기간: 2026-01-01 ~ 2026-06-30
금액: 74,170 JPY
수량: 23
신고일자: 2026-06-30
환율: 2026년 6월 공식 월평균환율
```

수동으로 계산한 단순 평균이나 기간 일평균으로 대체하지 않는다.

# 5. 환율 예외 규칙

## 5.1 기본 수집 기간

신고기간 시작일부터만 수집하면 1월 1일이 휴일일 때 직전 영업일 환율을 찾을 수 없다.

따라서 내부 환율 수집은 실제 신고기간 시작일보다 **7일 전부터** 수행한다.

예:

```text
실제 신고기간: 2026-01-01 ~ 2026-06-30
내부 수집 시작: 2025-12-25
환율 시트 표시 시작: 2026-01-01
```

즉, 내부 데이터는 7일 전부터 수집하되 `환율(통화)` 시트에는 실제 신고기간만 표시한다.

## 5.2 휴일·주말

해당 날짜 환율이 없으면 직전 영업일 매매기준율을 적용한다.

## 5.3 100통화 단위 통화

서울외국환중개는 아래 통화를 100통화 단위로 고시한다.

```text
JPY
IDR
VND
```

### 환율 시트 표시

`환율(JPY)`, `환율(IDR)`, `환율(VND)` 시트는 서울외국환중개 원문과 같은 **100통화 단위 값**을 유지한다.

예:

```text
서울외국환중개 JPY: 936.78원 / 100엔
환율(JPY) 시트: 936.78
```

### 실제 적용환율

소포수령증·통화 시트·영세율·수출실적에는 100으로 나눈 **1통화 단위 환율**을 사용한다.

```text
936.78 / 100 = 9.3678원 / 1엔
5.50 / 100 = 0.0550원 / 1동
```

### 적용환율 표시 자릿수

JPY·IDR·VND의 1통화 적용환율은 소수점 넷째 자리까지 표시한다.

적용 위치:

- 쇼피 소포수령증 시트
- 라자다 소포수령증/상세 시트
- 큐텐 소포수령증 시트
- 이베이 관련 시트
- `JPY`, `IDR`, `VND` 통화 시트
- 영세율첨부서류제출명세서
- 수출실적명세서

예:

```text
VND 적용환율: 0.0550
JPY 적용환율: 9.3678
```

`0.0550`을 셀 서식 때문에 `0.06`으로 보이게 하지 말 것.

### 원화 계산

1통화 단위 적용환율과 일치해야 한다.

```text
106,000 VND × 0.0550 = 5,830원
```

### 구형 캐시 혼합 대응

기존 CSV에 100통화 값과 1통화 값이 섞여 있을 수 있다.

- 이미 1통화 단위인 값을 다시 100으로 나누지 않는다.
- 100통화 단위인 값을 나누지 않고 적용하는 오류도 막는다.
- 환율 시트에 표시할 때는 다시 서울외국환중개 원문 단위로 정규화한다.

# 6. 환율 CSV 저장·재사용

v54의 환율 모듈은 아래 CSV 캐시를 사용한다.

```text
data/exchange_rate_cache.csv
data/monthly_exchange_rate_cache.csv
```

### 동작 원칙

1. 필요한 통화·기간이 CSV에 있으면 저장값을 사용한다.
2. 없는 날짜나 월만 추가 수집한다.
3. 같은 프로젝트 폴더에서 로컬 실행하면 앱 재시작 후에도 CSV가 유지된다.

### Streamlit Cloud 등 배포 환경 주의

실행 중 생성된 파일은 인스턴스 재시작·재배포 때 사라질 수 있다.

지속적으로 재사용하려면 다음 중 하나가 필요하다.

- 생성된 CSV를 GitHub 저장소의 `data/` 폴더에 커밋
- 외부 DB/스토리지 사용
- 영구 볼륨 마운트

가장 단순한 현재 운영 방식은 환율 수집 후 아래 두 파일을 GitHub에 올리는 것이다.

```text
data/exchange_rate_cache.csv
data/monthly_exchange_rate_cache.csv
```

단, 새로운 날짜가 필요하면 부족분만 다시 수집하게 한다.

# 8. 수출실적명세서 규칙

- 기본 체크는 해제 상태
- 수출신고번호: 공란
- 기타영세율건수: 항상 `1`
- 선(기)적일자: 플랫폼별 확정 날짜 사용
- JPY·IDR·VND 환율: 1통화 단위, 소수점 넷째 자리
- 큐텐: 반기말 날짜 + 6월/12월 공식 월평균환율

# 9. 통화 시트 규칙

통화별 시트 예:

```text
MYR
PHP
SGD
THB
VND
JPY
```

- 거래를 날짜순으로 정렬
- 같은 통화의 여러 원본을 하나로 합산
- JPY·IDR·VND 환율은 1통화 단위로 표시
- JPY·IDR·VND 환율 셀 표시 형식은 소수점 넷째 자리
- 큐텐 JPY 거래 날짜는 반기말
- 큐텐 JPY 환율은 해당 반기말 월 공식 월평균

# 10. 금지되는 회귀

아래 동작이 다시 나타나면 회귀 버그로 간주한다.

1. 사업자명 미확인 시 `유엠` 또는 `UM` 자동 입력
2. 수출실적명세서가 기본 체크됨
3. 큐텐 날짜가 PDF 작성일인 7월/다음 해 1월로 잡힘
4. 큐텐이 일별환율 또는 거래기간 단순평균을 사용함
5. `환율(JPY/VND/IDR)` 시트에서 1통화 단위 값이 표시됨
6. 실제 적용 문서에서 JPY·VND·IDR 100통화 원문값을 그대로 곱함
7. VND 환율 `0.0550`이 `0.06`처럼 두 자리만 표시됨
8. 라자다 Excel에서 같은 주문번호 행을 중복 제거함
9. 라자다 Excel 날짜를 주문일 등 다른 열로 사용함
10. `라자다(주문내역)`을 임의 집계표로 재작성함
11. `라자다(통화)` 시트에 `원본파일` 열이 다시 생김
12. 사용하지 않은 플랫폼이 총집계에 빈 행으로 나타남
13. 동일 통화 쇼피 PDF 여러 개가 원본 시트 하나로 덮어써짐
14. 앱 재시작 없이 코드가 반영됐다고 단정함

# 11. 권장 회귀 테스트

## 테스트 A: 100통화 단위

입력:

```text
VND 서울외국환중개 원문환율 = 5.50
외화금액 = 106,000 VND
```

기대 결과:

```text
환율(VND) 시트 = 5.50
소포수령증 환율 = 0.0550
VND 통화 시트 환율 = 0.0550
영세율명세서 환율 = 0.0550
수출실적명세서 환율 = 0.0550
원화금액 = 5,830원
```

## 테스트 B: 큐텐 상반기

입력:

```text
거래기간 = 2026-01-01 ~ 2026-06-30
작성일 = 2026-07-10
금액 = 74,170 JPY
```

기대 결과:

```text
집계월 = 2026년 06월
선적일자 = 2026-06-30
영세율 발급일자 = 2026-06-30
영세율 선적일자 = 2026-06-30
수출실적 선(기)적일자 = 2026-06-30
환율 = 2026년 6월 공식 월평균 JPY 환율 / 100
환율(JPY) 시트 월평균 표 = 공식 100엔 단위 값
```

## 테스트 C: 라자다 Excel 3개

입력:

- 라자다 베트남
- 라자다 싱가포르
- 라자다 태국

기대 결과:

```text
VND 23행 / 8,087,839
SGD 63행 / 1,242.86
THB 89행 / 48,281.89
```

`라자다(주문내역)`은 각 원본 전체가 빈 행 1줄 간격으로 이어 붙어야 한다.

`라자다(VND/SGD/THB)` 시트에는 `원본파일` 열이 없어야 한다.

## 테스트 D: 사업자 정보 없음

기대 결과:

```text
사업자명(사업자번호)
```

어디에도 `유엠`, `UM`이 자동 입력되면 안 된다.

# 13. 다른 GPT에게 바로 전달할 압축 프롬프트

아래 블록만 복사해도 핵심 지시로 사용할 수 있다.

```text
이 프로젝트는 Streamlit 기반 해외 소포수령증/매출집계 자동화 앱이며 기준 버전은 v54다. v55가 아니라 v54에서 수정하라.

절대 회귀시키지 말아야 할 규칙:
1) 사업자명 미확인 시 유엠/UM 금지, 기본값은 "사업자명(사업자번호)". 사업자번호·대표자·주소는 공란.
2) 수출실적명세서 체크박스 기본값은 False.
3) 큐텐재팬은 거래기간 반기말(상반기 6/30, 하반기 12/31)을 월별집계·JPY시트·영세율 발급/선적일·수출실적 선적일에 사용.
4) 큐텐재팬 환율은 해당 반기말 월(6월/12월)의 서울외국환중개 공식 월평균 JPY 환율만 사용. 총집계·월별집계·JPY시트·소포수령증·영세율·수출실적에 동일 적용.
5) 이베이는 공식 월평균환율 사용.
6) JPY/IDR/VND는 서울외국환중개가 100통화 단위로 고시한다. 환율(JPY/IDR/VND) 시트에는 원문 100통화 값을 유지하고, 실제 소포수령증·통화시트·영세율·수출실적에는 /100한 1통화 환율을 소수점 4자리로 표시한다. 예: VND 5.50 -> 0.0550, JPY 936.78 -> 9.3678.
7) 환율 수집은 신고기간 시작 7일 전부터 하되 환율 시트는 실제 기간만 표시. 휴일은 직전 영업일.
8) 라자다 주문 Excel은 paidPrice=매출금액, deliveredDate=매출일/선적일/환율일/월별집계일. 같은 주문번호 행도 중복 제거 금지.
9) 라자다(주문내역) 시트는 업로드한 국가별 원본 Excel 전체 열·값·서식을 그대로 복사하고 빈 행 1줄을 사이에 두고 아래로 이어 붙인다.
10) 라자다(통화) 시트 열은 No, 배송완료일, 주문번호, 주문상품번호, 송장번호, 배송사, 외화금액, 환율, 원화금액의 9개이며 원본파일 열은 금지.
11) 쇼피 같은 통화 PDF 여러 개는 쇼피(MYR)(1), (2)처럼 원본 시트를 분리하고 MYR 통화 시트는 날짜순 통합.
12) 수출신고번호 공란, 기타영세율건수 1, 영세율명세서 L/C 번호 칸에는 트래킹번호.

14) 코드 교체 후 Streamlit 앱 프로세스를 재시작해야 이전 모듈 캐시가 사라질 수 있다.

```
