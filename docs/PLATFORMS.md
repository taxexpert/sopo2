# 플랫폼별 입력 포맷 · 판별 규칙 · 환율 규칙

이 문서는 `modules/pdf_parser.py`, `modules/lazada_order_parser.py`, `modules/shopify_parser.py`
가 실제로 무엇을 읽고 어떤 값을 매출로 인식하는지 정리한 것입니다.
새 자료가 들어왔을 때 "이 규칙이 아직 맞는지" 확인하는 체크리스트로 쓰세요.

---

## 공통 — 환불·취소 처리 규칙 (2026-07-29 결정, 전 플랫폼 적용)

주문 상태 정보가 있는 입력(쇼피파이 orders, 라자다 주문내역 Excel)에 적용합니다.
소포수령증 PDF에는 배송분만 기재되므로 해당 없음.

| 상태 | 처리 |
|---|---|
| `partially_refunded` (부분환불) | **반영** — `Total` 전액 |
| `refunded` (전액환불) | **미반영** |
| `voided` (취소) | **미반영** |
| 미배송(`Fulfilled at`/`deliveredDate` 없음) | **미반영** |
| 라자다 `status` 에 refund/return/cancel 포함 | **미반영** |

미반영 건은 조용히 버리지 않습니다:
- 파서 결과에 사유별 집계(`skipped_by_reason`)와 건별 상세(`skipped_items`)를 보존
- 처리 로그에 사유별 건수 표시
- **시트에는 정상 건과 같은 형식의 행으로 표시** — 구분 열(취소/전액환불/미배송/반품)과
  회색 배경으로 한눈에 구분되며, 환율·원화는 비우고 합계에 넣지 않습니다

**행 배치 규칙 (2026-07-30 사용자 지정)**: ① 매출 반영 건(paid·partially_refunded)을 먼저
모아서 표시 → ② 바로 아래 `합계(매출 반영)` → ③ 그 아래 전액환불(refunded) 건들 →
④ 그 아래 취소(voided)·미배송 건들 순으로 나열합니다.

## 공통 — 시트 출력 필수항목 (사용자 지정, 지시 없이 삭제·변경 금지)

| 시트 | 필수 열 | 필수 행 |
|---|---|---|
| **Joom** | 서비스 / 발송날짜 / Order ID / 도착국가 / 접수번호 / 금액 / 적용환율 / 원화금액 / **상품명** | 조회기간 해외배송 합계, **PDF 합계 표기** |
| **쇼피파이** | No / 주문번호 / 구분 / 배송완료일 / 결제상태 / 통화 / 외화금액 / 환율 / 원화금액 / **상품명** | 합계(매출 반영) |
| **라자다 상세** | No / 배송완료일 / 주문번호 / 주문상품번호 / 송장번호 / 배송사 / 외화금액 / 환율 / 원화금액 / 비고 | 합계(매출 반영) |

## 공통 — 플랫폼 판별 순서

1. **파일명** — `라자다`, `큐텐`, `이베이`/`린코스`, `joom`, `_MY_`·`_TW_` 같은 국가코드 등
2. **본문 표식** — PDF 텍스트에서 배송업체명/양식 고유 문구 탐지
3. **사용자 선택** — 1·2로도 판별이 안 되면 STEP 1 화면에서 직접 고르게 함

Excel/CSV는 파일명이 아니라 **필수 열 조합**으로 판별합니다.

## 1. 쇼피 (Shopee) — 두라로지스틱스

| 항목 | 값 |
|---|---|
| 입력 | 소포수령증 PDF (텍스트 기반) |
| 판별 | 파일명 `유엠(UM)_` 또는 `_MY_`·`_PH_`·`_SG_`·`_TH_`·`_TW_`·`_VN_`·`_BR_`·`_MX_` / 본문 `두라로지스틱스` + `운송장번호` |
| 파서 | `parse_shopee_pdf()` |
| 매출 인식 | `3. 해외배송 내역` 표의 **거래별 행** (배송업체·발행일·운송장번호·도착국가·수량·수출신고금액) |
| 통화 | 파일명 국가코드 → `COUNTRY_TO_CURRENCY`, 없으면 본문 `통화 XXX` |
| 적용환율 | 각 거래의 **발행일(`date`) 일별 매매기준율** |
| 시트 | `쇼피(MYR)` 등. 같은 통화 PDF가 여러 개면 `쇼피(MYR)(1)`, `(2)` … |

## 2. 라자다 (Lazada) — 용성종합물류

두 가지 입력을 모두 받습니다.

### 2-1. 소포수령증 PDF
| 항목 | 값 |
|---|---|
| 판별 | 파일명 `라자다`/`lazada`, 본문 `용성종합물류` |
| 파서 | `parse_lazada_pdf()` |
| 매출 인식 | `라자다 <배송사> <출발> <도착> <발송번호> <n>건 <금액>(<통화>)` 요약 행 |
| 적용환율 | 거래기간 **평균** 매매기준율 |

### 2-2. 주문내역 Excel (`.xlsx` / `.xlsm`)
| 항목 | 값 |
|---|---|
| 판별 | 시트 헤더에 `deliveredDate` **와** `paidPrice` 가 함께 존재 |
| 파서 | `parse_lazada_order_excel()` |
| 매출 인식 | 행 단위 `paidPrice`. **한 주문에 상품이 여러 개면 각 행을 각각 매출로 반영**(주문번호 중복 제거 안 함) |
| 제외 | `deliveredDate` 없음 → 스킵 / `paidPrice` 0 → 스킵 |
| 통화 | `shippingCountry` (없으면 파일명) → `COUNTRY_INFO` |
| 적용환율 | `deliveredDate` **일별** 매매기준율 |
| 시트 | `라자다(주문내역)` — 업로드한 원본 xlsx 시트를 서식 그대로 세로로 이어붙임 |

## 3. 큐텐재팬 (Qoo10) — 국제로지스틱

| 항목 | 값 |
|---|---|
| 입력 | 소포수령증 PDF (텍스트형 / 이미지형은 OCR) |
| 판별 | 파일명 `큐텐`/`qoo10` / 본문 `Qoo10`+`국제로지스틱` 또는 `금액(JPY)`+`국제로지스틱` |
| 파서 | `parse_qoo10_pdf()` → 표 우선, 실패 시 텍스트 정규식, 그래도 실패 시 `pytesseract` OCR |
| 매출 인식 | `3. 해외배송 내역서` 의 발송수량·금액(JPY) |
| 수동 보완 | 자동인식 실패 시 STEP 2 화면에서 기간/금액/건수/발송번호/발행일 직접 입력 |
| 통화 | JPY 고정 |
| 적용환율 | 거래기간이 속한 **반기말(6월 또는 12월)의 공식 월평균 매매기준율** |
| 신고 기준일 | 거래기간 **종료일** (없으면 반기말 6/30 · 12/31) |
| 시트 | `큐텐(소포수령증)`, `JPY` |

> ⚠️ JPY는 SMBS가 100엔 단위로 고시합니다. 내부 계산은 1엔 단위(소수 4자리)로 정규화합니다.

## 4. 린코스(주) — 이베이 등

`이베이_해외소포수령증_*.pdf` 로 들어오지만 **실제 발급 주체는 린코스(주)** 이며,
한 장의 수령증 안에 **여러 통화가 섞여** 있습니다 (USD·CAD·EUR·GBP·AUD …).

| 항목 | 값 |
|---|---|
| 판별 | 파일명 `이베이`/`ebay`/`린코스`/`lincos` / 본문 `린코스`·`lincos` |
| 파서 | `parse_ebay_lincos_pdf()` |
| 매출 인식 | **`3. 해외배송 내역서`** 표 — `발행월 / 해외배송업체 / 배송국가·Service / 통화단위 / 발송수량 / 신고금액` |
| 참고 표시 | `2. 해외배송 소포 수령증` 요약 표는 `summary_items` 로 시트 표시용으로만 보관 (집계에 미사용) |
| 발행월 병합셀 | 첫 행에만 `2025-01` 이 들어오고 이후 행은 빈 칸 → 마지막 값을 이어서 적용 |
| 통화 | 행별 `통화단위` 열 (혼합) |
| 적용환율 | 각 행의 **발행월 공식 월평균 매매기준율** |
| 선(기)적일자 | 발행월의 **말일** |
| 시트 | `이베이` (여러 장이면 `이베이(1)`, `(2)` …) |

## 5. Joom — 에이치3네트웍스 (H3 NETWORKS)

양식명은 **`[상품 수령 및 운송 확인증]`** (Certificate of Receipt and Transportation of Product).

| 항목 | 값 |
|---|---|
| 입력 | PDF (텍스트 기반) |
| 판별 | 본문 `상품 수령 및 운송 확인증` / `H3 NETWORKS` / `에이치3네트웍스`, 파일명 `joom`·`조옴` |
| 파서 | `parse_joom_pdf()` |
| 제출업체 정보 | `1. 제출업체 정보` 표 — 사업자등록번호 / 법인명 / 대표자 성명 / 법인 주소 / **조회기간** / 작성일자 |
| 매출 인식 | `2. 해외배송 내역서` 표의 **건별 행** — `서비스 / 발송날짜 / Order ID / 도착국가 / 접수번호 / 금액(USD) / 상품명` |
| 합계 검증 | 마지막 `조회기간 해외배송 합계 USD 254.83` 행을 파싱해 건별 합계와 대조 (`total_mismatch` 플래그) |
| 통화 | **USD 고정** (헤더 `금액(USD)` 에서 통화코드를 읽어 다른 통화도 대응) |
| 수량 | 행당 1건 |
| 적용환율 | **발송날짜 일별** 매매기준율 (휴일은 직전 영업일) |
| 시트 | `Joom` (여러 장이면 `Joom(1)`, `(2)` …) |

## 6. 쇼피파이 (Shopify)

Shopify 관리자에서 내려받은 **orders export** 를 사용합니다.
`transaction`, `payout` CSV는 참고자료일 뿐 **집계에 쓰지 않습니다.**

| 항목 | 값 |
|---|---|
| 입력 | `<스토어명> orders <기간>.csv` (또는 `.xlsx`) |
| 판별 | 헤더에 `Name`, `Financial Status`, `Fulfilled at`, `Currency`, `Total`, `Lineitem quantity` 가 함께 존재 |
| 파서 | `parse_shopify_orders()` |
| 스토어명 | 파일명에서 ` orders` 앞부분 (`FRESORY orders 26년.csv` → `FRESORY`). 없으면 파일 stem |
| 매출 인식 | **`Total` 열** (상품가 + 배송비 + 세금 포함) |
| 기준일 | **`Fulfilled at`** 의 날짜 부분 |
| 제외 | 같은 주문의 2번째 이후 라인아이템 행(`Total` 비어 있음) → 스킵 |
| 환불·취소 | 아래 **공통 환불 규칙** 적용 |
| 통화 | `Currency` 열 (USD) |
| 적용환율 | `Fulfilled at` 날짜의 **일별** 매매기준율 (휴일은 직전 영업일) |
| 시트 | `쇼피파이(FRESORY)` — 원본 열을 그대로 두고 `날짜`(F 뒤), `환율`·`원화`(Total 뒤) 3개 열을 삽입 |

### 참고 — 수기 작성본과의 차이

고객이 보내온 `2. 매출집계(유월오렌지).xlsx` 수기본에는 다음 두 가지가 있습니다. 앱은 **따르지 않습니다.**

1. `총` 시트의 **외화 합계가 전체 열 SUM** 이라 `voided` 주문 금액까지 포함되어 있음
   (원화 합계는 정상). → 앱은 인식된 행만 합산합니다.
2. `2026-01-01` 같은 연초 휴일에 **다음 영업일(01-02)** 환율을 쓴 곳이 있음.
   → 앱은 다른 플랫폼과 동일하게 **직전 영업일** 환율을 사용합니다.
