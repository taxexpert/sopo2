# 검증 기준표 — 소포수령증 매출집계

**검증 대상 목표:** 업로드된 원본 자료(PDF/CSV/Excel)가 누락·중복 없이 파싱되고,
올바른 환율로 환산되어, 매출집계 워크북과 신고서류(영세율첨부서류제출명세서·수출실적명세서)에
정확히 반영된다.

검증은 성격이 다른 축들로 돌려 상호 보완한다. 관측 지점이 겹치지 않는 것이 핵심이다.

1. **회귀 축** (A-1, E-3): fixtures + expected로 자동 반복 — 코드 변경 때마다 돌리는 기본 안전망
   → `python tools/quick_check.py`
2. **독립 대사 축** (A-2, A-3): 생성 로직과 무관한 경로로 원본을 다시 세어보기
   (`sales-summary-verifier` 에이전트). 회귀 축이 못 잡는 "기대값 자체가 틀린" 경우를 잡음
3. **규칙 축** (B, D, E): 숫자가 우연히 맞아도 규칙(환율 기준일, 헤더 위치, 큐텐 예외)이
   어긋나면 잡아내는 층
4. **산출물 감사 축** (A-4, A-5, B-2, C-3, D-1~D-4, E-2): 입력도 정답지도 믿지 않고
   **생성된 xlsx의 셀 값만** 읽어 서로 대사한다. `expected/`를 읽지 않는다
   → `python tools/audit_workbook.py --build all`
5. **실경로 축** (B-5 + 위 전부): `app.py:733-961` 인라인 오케스트레이션을 streamlit
   `AppTest`로 그대로 통과시킨다. 다른 축은 모듈을 직접 조립하므로 이 경로를 지나지 않는다
   → `python tools/e2e_apptest.py`
6. **메타모픽 축** (B-1, B-3, B-4, C-1, C-4, E-1, E-3): 정답을 몰라도 규칙 위반을 잡는다.
   입력을 변형했을 때 결과가 **변해야/변하지 않아야** 하는 관계로 판정하며 `expected/`를
   읽지 않는다 → `python tools/metamorphic_check.py`

## C. 완전성 — 빠지거나 겹치지 않았는가

| # | 검증 항목 | 합격 기준 | 검증 방법 |
|---|---|---|---|
| C-1 | 누락 없음 | 원본 거래 수 = 시트 데이터행 수 + 의도적 제외 수 | 원본 재카운트 후 `skipped_unfulfilled`·`skipped_blank`와 합산 대조 |
| C-2 | 제외 사유 명시 | 제외된 행마다 사유가 분류됨 (미배송·빈 행 등), 사유 없는 소실 0건 | 쇼피파이 `row_flags`의 `counted=False` 행 전수 확인 |
| C-3 | 중복 없음 | 확정 중복(파일 동일·강한 키+내용 동일)은 `modules/dedup_guard.py`가 자동 제외하고, 내용이 다른 충돌은 생성을 중단함. 단 강한 키 없는 자료(이베이 월집계·큐텐 수동)는 경고만 나오므로 수동 확인 필요. **주의: 라자다 동일 주문번호 다행은 정상이라 중복이 아님** | 처리 로그의 `[중복]`/`[WARN]` 확인 + 강한 키 없는 자료는 통화별 시트에서 직접 대조 |
| C-4 | 다중 파일 병합 | TH처럼 기간이 쪼개진 파일(10~11월 + 12월)이 합산도 되고 이중계상도 안 됨 | shopee 9개 PDF 일괄 처리 후 국가별 합계 확인 |

## D. 구조 — 산출물 형식이 맞는가

| # | 검증 항목 | 합격 기준 | 검증 방법 |
|---|---|---|---|
| D-1 | 시트 구성 | 총집계/월별집계/통화별/플랫폼 원본/환율 시트가 모두 존재, `keep_sheets` 미등록으로 삭제된 시트 없음 | 생성 워크북 시트 목록 대조 |
| D-2 | 헤더 위치 | 통화 시트는 1~5행 요약·6행 헤더·7행 데이터, **JPY(큐텐) 시트만 4행 헤더** — 어긋나면 수출신고 프로그램 업로드 실패 | 각 통화 시트 헤더 행 위치 확인 |
| D-3 | 신고서류 필수 필드 | 수출신고번호/기타영세율건수/선적일자/통화/환율/외화/원화 컬럼 채워짐, `_company_name()` 제출자 정상 추출 | extra_docs 산출물 셀 검사 |
| D-4 | 원본 재현 | 쇼피파이 원본 시트가 `headers`+`rows`로 원본 CSV 전 행을 그대로 재현 | 원본 CSV와 셀 단위 비교 |

> D-4 주의 — 커밋 `ab82a8f`("출력 엑셀을 간결한 표로 정리") 이후 `write_shopify_sheet`는
> 원본 덤프가 아니라 10열 요약표(3행 헤더)를 쓴다. 즉 위 합격 기준은 **현재 구현과 어긋난다.**
> `tools/audit_workbook.py`는 그래서 '전 건이 설명되는가'로 판정한다 —
> 시트 반영행 + 미반영행 + `skipped_blank`(라인아이템 연속행) = 원본 CSV 데이터 행 수.
> 기준을 어느 쪽으로 확정할지는 미결정 사항이다.
