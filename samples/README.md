# samples/ — 회귀 검증용 예시 자료

## 저장소에 올라가는 것 / 안 올라가는 것

| | 대상 | 이유 |
|---|---|---|
| ✅ **올라감** | `README.md`, 폴더 구조(`.gitkeep`), `expected/summary.json`, `fixtures/*.csv` | 숫자·구조뿐이라 개인정보 없음 |
| ❌ **제외** | `*/input/*`, `*/reference/*` 의 실제 파일 | 사업자번호·구매자 이름·이메일·주소·전화번호 포함 |

그래서 저장소를 새로 clone 하면 **구조와 정답지는 그대로 있고 `input/` 만 비어 있습니다.**
팀원이 검증을 돌리려면 실제 파일만 별도로 전달받아 `input/` 에 넣으면 됩니다.

---

## 폴더 구조

```
samples/
├── fixtures/                       ← 환율 고정본 (외부 사이트 상태와 무관하게 재현)
│   ├── exchange_rate_cache.csv          일별 매매기준율
│   └── monthly_exchange_rate_cache.csv  공식 월평균 매매기준율
│
└── <플랫폼>/
    ├── input/       앱에 실제로 넣는 파일 — 이것만 처리 대상  (git 제외)
    ├── reference/   참고자료 (고객 수기 매출집계, transaction·payout 등)  (git 제외)
    └── expected/
        └── summary.json   확정 숫자 (건수·수량·외화·원화)
```

플랫폼 폴더 하나 = 앱이 지원하는 플랫폼 하나. 나중에 플랫폼을 레지스트리 구조로 바꾸면
`samples/<플랫폼>` 과 `modules/<플랫폼>_parser.py` 가 1:1로 대응됩니다.

### 환율 고정본(fixtures) 쓰는 법

서울외국환중개 접속 없이 같은 결과를 재현하려면 실행 전에 복사합니다.

```bash
cp samples/fixtures/*.csv data/
```

환율만 반기말 월평균으로 통일 — 큐텐만의 예외 규칙).

## expected/summary.json 형식

```json
{
  "platform": "shopify",
  "description": "쇼피파이 orders export (정지민 26년 자료)",
  "rate_basis": "daily (Fulfilled at)",
  "source_files": ["FRESORY orders 26년.csv", "..."],
  "expected_total_krw": 1704177,
  "expected": {
    "files": 3,
    "by_currency": {
      "USD": { "count": 22, "qty": 22, "fx": 1174.51, "krw": 1704177 }
    },
    "by_store": {
      "FRESORY": { "USD": {...}, "skipped_unfulfilled": 2, "skipped_blank": 1 }
    }
  }
}
```

| 필드 | 뜻 |
|---|---|
| `count` | 매출로 인식한 **행 수** |
| `qty` | 발송 **수량** 합계 (린코스처럼 한 행에 여러 건인 경우 count ≠ qty) |
| `fx` | 외화 합계 (**통화별로만** 의미 있음 — 서로 다른 통화는 합산 불가) |
| `krw` | 행별로 환산해 더한 원화 합계 |
| `skipped_*` | 매출에서 **제외한** 행 수 (쇼피파이 미배송·취소 등) |

## 기대값을 바꿔야 할 때

숫자가 틀려서가 아니라 **규칙이 바뀌어서** 값이 달라지는 경우가 있습니다.
(예: 환불분을 차감하기로 결정 → 쇼피파이 1,704,177 → 1,671,493)

이때는 반드시 **왜 바뀌었는지**를 아래에 남기세요. 안 그러면 다음에 회귀인지
의도된 변경인지 구분할 수 없습니다.
